# Probe-target-aware Dreamer experiment

2026-11-18. Protocol fixed before training and fresh test collection.

Question: can upstream DreamerV3 learn measured probe-target/concurrency transitions and retain reliable diagnosis when supplied the informative ledger probe? This is feasibility, not an autonomous probing policy or a claim of superiority.

Reuse the 64 completed pilot incidents (development seed 9101 and replacement test seed 9103) as this new experiment's training set. The earlier pilot result remains historical; those 32 former test rows are explicitly training data here. No other pilot/failure rows are used. Each trajectory contains eight chronological observations: four base checkout windows, then the two extra-target pairs in their measured order. Both probe targets and both concurrency levels are represented. No fabricated action-conditioned transitions or counterfactual replay.

Train a fresh size1m upstream DreamerV3 checkpoint, seed 91, for 100,000 environment steps using the established configuration and training-only mechanism supervision. A separate 256-step smoke checkpoint must pass actual upstream action normalization, label isolation, posterior extraction and prior forecasting before the full run. Do not initialize from the incompatible workload-only checkpoint.

Action contract: two bounded float32 values, probe target (checkout=0, ledger=1) and concurrency/12. Upstream wrappers normalize both to [-1,1]. The initial observation has no preceding measured action; each later observation must match its recorded target/concurrency. A zero raw action leads only to terminal bookkeeping. Observations contain log trace latencies, measured target/concurrency, an upstream-observation mask, declared next action, time index, complete-evidence flags, and ledger error rate. Fault labels, settings and CPU/pool/database counters are excluded. Auxiliary targets remain outside encoder/decoder/policy inputs and apply only after the eighth observation.

After training, extract features for all 64 training incidents. Select readout configuration among the existing eight candidates by leave-one-repeat-out CV on training data only (four groups, balanced across both source seeds). Fit and freeze readouts before test collection. Primary: final Dreamer latent state. Controls: the pilot's 17-dimensional base-plus-ledger response representation, all eight observations flattened, and their concatenation. Also report auxiliary diagnosis and a shuffled-label latent control. All legitimate controls receive the same measured evidence. Readout CV is development only: the world model trained on those same rows.

Collect 32 fresh incidents, seed 9202, four per family, using the identical bounded collector (3/9 concurrency, balanced phase/order, all eight observations). No rerolls, threshold changes or test-time fitting. Preserve partial logs/data on interruption; any operational replacement needs an explicit recorded amendment and new seed. Score all three mechanisms exactly. Feasibility gate: primary >=29/32, healthy 4/4, every family >=3/4, no more than one fewer correct than the strongest legitimate telemetry control, and next-ledger-log-latency MSE below persistence. Separately report any diagnostic advantage without treating feasibility as superiority. Report forecasts by within-target versus switched-target transitions, paired comparisons, and timing.

The checkpoint and readouts must remain unchanged through test extraction. Verify fitted parameters, source/data hashes, balanced valid cases, action carry alignment and absence of label inputs. Do not promote to serving. All staging, training, fault collection, results and cleanup stay in systems-world-model-lab; restore the previous inference template and replicas. Monitoring outages must not kill or restart a healthy job. Save artifacts on the namespace PVC and export evidence read-only afterward.
